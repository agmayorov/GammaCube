# GammaCube

## Command Line Interface (CLI)

Проект поддерживает запуск как в интерактивном режиме с визуализацией, так и в батчевом режиме через macro-файл.

### Основные параметры

- `-i, --input`  
  Путь к входному **macro-файлу** с командами для батчевого режима (например, `run.mac`).  
  Если параметр **не указан**, приложение запускается в режиме визуализации.  
  Если параметр **указан**, флаги `-noUI`, `-vd` и `--view-deg` игнорируются.

- `-o, --output-file`  
  Имя выходного `.root` файла.  
  По умолчанию: `GammaCube`.

- `-t, --threads`  
  Количество потоков для многопоточного режима.  
  По умолчанию используется максимальное доступное число ядер.

- `--bins`  
  Количество бинов в выходных гистограммах.

- `-s, --seed`  
  Seed генератора случайных чисел. Используемое значение записывается в `info_*.txt`.  
  По умолчанию: текущее время. Одинаковый seed воспроизводит результат только при одинаковом `-t`.

### Параметры сцинтилляции и порогов

- `-ys, --yield-scale`  
  Масштабирование параметра `SCINTILLATIONYIELD` для сцинтилляторов.  
  Например, при значении `1000` `SCINTILLATIONYIELD` будет разделён на 1000.  
  По умолчанию: `1`.

- `-ct, --crystal-threshold`  
  Нижний порог регистрации энерговыделений в кристалле.  
  По умолчанию: `0` МэВ (значение задаётся в МэВ).

- `-vt, --veto-threshold`  
  Нижний порог регистрации энерговыделений в системе антисовпадений.  
  По умолчанию: `0` МэВ (значение задаётся в МэВ).

- `--trigger`  
  Условие, при котором частица считается зарегистрированной.  
  `gamma` — кристалл и нет вето (`Crystal && !Veto`);
  `charged` — кристалл и вето, верхний стакан или нижнее (`Crystal && (Veto || BottomVeto)`).
  Действует одинаково на энерговыделения и на фотоэлектроны с теми же порогами;
  от него зависят `N_trig`, эффективная площадь / чувствительность, `Rate_Real`, колонки `trigger` в CSV и
  `trig_edep.csv`. Блоки `Counts` в `info_*.txt` по-прежнему содержат оба числа (`Crystal_only`,
  `Veto_then_Crystal`). Для `charged` к именам вывода добавляется `_trigger-charged`.  
  По умолчанию: `gamma`.

- `-oct, --crystal-optic-threshold`  
  Нижний порог регистрации **оптических фотонов** в кристалле.  
  По умолчанию: `0`.

- `-ovt, --veto-optic-threshold`  
  Нижний порог регистрации оптических фотонов в верхнебоковой системе антисовпадений.  
  По умолчанию: `0`.

- `-obvt, --bottom-veto-threshold`  
  Нижний порог регистрации оптических фотонов в нижней системе антисовпадений.  
  По умолчанию: `0`.

- `-ptl, --photon-time-limit`  
  Длительность окна регистрации (ворот) в **мкс**. Оптический фотон, доживший
  до конца окна, убивается и в SiPM не попадает — так же, как его не увидела бы
  реальная электроника. Окно открывается от первого энерговыделения в событии,
  поэтому задержанные распады отсчитываются от своего взаимодействия, а не от
  `t = 0`. Работает только вместе с `--use-optics`, иначе игнорируется.
  Сколько фотонов было убито, пишется в `info_*.txt` (`Killed_photons`).
  Для CsI (τ = 1 мкс) окно 12 мкс теряет ~6·10⁻⁶ фотонов, 3 мкс — ~5 %, 1 мкс — ~37 %.  
  По умолчанию: выключено.

### Модель SiPM

Все три параметра работают только вместе с `--use-optics` и применяются ко всем SiPM
(кристалл, вето, нижнее вето). Для стоящего в детекторе **onsemi MicroFC-60035-SMT**
(6×6 мм, ячейка 35 мкм) это `-sc 18980 -sr 95 -xt 0.08`.

- `-sc, --sipm-cells`  
  Число микроячеек в одном канале. Детектированный фотон попадает в случайную ячейку
  и зажигает её, только если она успела перезарядиться — отсюда насыщение.  
  По умолчанию: `0` (насыщение выключено, каждый фотон даёт p.e.).

- `-sr, --sipm-recovery`  
  Постоянная времени перезарядки ячейки в **нс**; вероятность срабатывания
  `1 − exp(−Δt/τ)`. Имеет смысл только при `-sc > 0`.  
  По умолчанию: `95` (даташит MicroFC-60035, 6 мм / 35 мкм).

- `-xt, --sipm-crosstalk`  
  Вероятность оптического кросстолка: сработавшая ячейка с этой вероятностью зажигает
  соседнюю, та — следующую (геометрический каскад, среднее число лишних p.e. `p/(1−p)`).
  Для C-Series при перенапряжении 2.5 В это ≈ `0.08`, при 5 В — около `0.25`.  
  По умолчанию: `0` (выключено).

Фотон, попавший в неперезарядившуюся ячейку, поглощается и p.e. не даёт, но в ntuple
`photons` (при `--save-photons`) он по-прежнему записывается — там регистрируются
приходы фотонов на окно, а не сработавшие ячейки.

### Геометрия и визуализация

- `-gc, --geometry-config`  
  Конфигурация геометрии (см. раздел «Конфигурации геометрии»).  
  По умолчанию: `default`.  
  Доступные варианты: `default`, `tunacan`, `cubesat`, `experiment`.

- `--engine`  
  Двигатель в верхнем юните спутника. Только с `-gc tunacan` или `-gc cubesat`.  
  По умолчанию: нет.  
  Доступные варианты: `sputnix`, `geoscan`.

- `--camera [модель]`  
  Камера; без значения — `galper`. Только с `-gc tunacan` или `-gc cubesat`.  
  **Пока не размещается**: флаг заканчивается ошибкой, пока в `Layout` не задано положение камеры.

- `-vd, --view-deg`  
  Угол (в градусах), на который разрезается геометрия для просмотра внутренней структуры.  
  По умолчанию: `360`.

- `-vtr, --veto-top-rounded`  
  Радиус кривизны (в мм) для углов верхней части системы антисовпадений.  
  По умолчанию: `0`.

- `-vch, --veto-chamfer-height`  
  Высота (в мм) фаски верхней части системы антисовпадений.  
  По умолчанию: `0`.

- `-vd, --view-deg`  
  Угол (в градусах), на который разрезается геометрия для просмотра внутренней структуры.  
  По умолчанию: `0`.

- `-noUI`  
  Запуск без визуализации.

### Детектор и источник частиц

- `-d, --detector`  
  Тип внутреннего кристалла.  
  По умолчанию: `CsI`.  
  Доступные варианты: `CsI`, `NaI`.

- `-sipm, --crystal-sipm-config, -csc`  
  Конфигурация SiPM для кристалла.  
  По умолчанию: `12-cross`.  
  Доступные варианты: `2x2`, `8-circle`, `12-cross`, `12-circle`, `12-rhombus`, `13-circle`, `16-cross`.

- `--polished`  
  Делает отражающие поверхности полностью зеркальными.  
  
- `-f, --flux-type`  
  Тип потока частиц.  
  По умолчанию: `Uniform`.  
  Доступные варианты: `Uniform`, `Galactic`, `PLAW`, `COMP`, `Table`, `SEP`.

- `-fd, --f-dir, --flux-dir`  
  Геометрия потока (см. раздел «Генерация частиц»).  
  По умолчанию: `isotropic`.  
  Доступные варианты: `isotropic`, `isotropic_up`, `isotropic_down`, `flat`, `point_beam`, `point_iso`.  
  Псевдонимы: `vertical_down` = `flat --theta 0`, `vertical_up` = `flat --theta 180`,
  `horizontal` = `flat --theta 90 --phi 0`.

- `--theta`, `--phi`  
  Направление, **откуда приходит** частица, в градусах. Для `flat`, `point_beam`, `point_iso`.  
  По умолчанию: `0`, `0`.

- `--source-r`  
  Расстояние точечного источника от оси цилиндра (мм). Для `point_beam`, `point_iso`.  
  По умолчанию: `R_b ≈ 81` мм — снаружи всей модели на любой высоте.  
  Меньшее значение допускается, только если точка не попадает в вещество (см. «Минимальный радиус»).

- `--source-z`  
  Высота точечного источника (мм, координата z геометрии). Для `point_beam`, `point_iso`.  
  По умолчанию: `0`.

- `--cone`  
  Полуугол раскрытия конуса (градусы, `0 < α ≤ 180`). Для `point_iso`.  
  По умолчанию: `180`.

### Дополнительные опции

- `--use-optics`  
  Включает оптическую физику.

- `--save-secondaries`  
  Сохраняет вторичные частицы в отдельный файл.

- `--save-optics`  
  Сохраняет энергию и координаты зарегистрированных фотонов.


## Конфигурации геометрии

Код геометрии лежит в `include/geometry/` и `src/geometry/`: `Detector` (NATALIA), `TunaCan`
(банка, Ti-пластина, нижний колпак), `CubeSat_GeoScan_3U`, `Engine`, `Camera` и их `*Sizes.hh`.
Что строится и где стоит, задаёт `Layout` (`src/geometry/Layout.cc`) — единственное место
с положениями NATALIA, двигателя и камеры; `Geometry` расставляет объёмы, `GenSurface` строит
по тем же числам огибающую генерации.

| `-gc`        | Что строится                                                        | Огибающая генерации                         |
|--------------|---------------------------------------------------------------------|---------------------------------------------|
| `default`    | NATALIA в TunaCan с Ti-пластиной, центр банки в начале координат     | цилиндр `R = 37` мм, `z ∈ [-44.9, 31.5]` мм |
| `tunacan`    | 3U CubeSat, NATALIA в TunaCan сверху верхнего юнита, `z = +195.4` мм | коробка `110.8 × 110.8` мм, `z ∈ [-170.25, 226.9]` мм |
| `cubesat`    | 3U CubeSat, NATALIA перевёрнута в центральном юните, `z = +3` мм     | коробка `110.8 × 110.8 × 340.5` мм          |
| `experiment` | только кристалл с оболочкой, стеклом, оптическим слоем, платой и SiPM; без вето, Tyvek снаружи кристалла, корпусов и TunaCan | цилиндр `R = 32` мм, `z ∈ [-43, 26.5]` мм |

- В конфигурациях со спутником центр спутника — начало координат, ось `+z` направлена к верхнему юниту.
  В `cubesat` NATALIA перевёрнута: `--theta 0` (приход сверху) бьёт в её дно.
- Для спутника Ti-пластина меньше: `plateSize = 78`, `plateCornerSize = 10` мм (габарит 98 мм вместо 100),
  чтобы влезть в 3U; размеры предварительные (`Layout::Configure`). В `default` — прежние `83 / 8.5`.
- `--engine sputnix` и `--engine geoscan` пока стоят в одном месте — в нижней части верхнего юнита
  (`Layout::EnginePosition`), поменять на реальные положения, когда они будут известны.
- В `experiment` вето не размещено, поэтому `Crystal_only` = все события со срабатыванием кристалла.
- В `tunacan` сфера `isotropic*` центрирована на верхе спутника, под Ti-пластиной
  (`z = CubeSat::halfZ - bracketHeight = 165.25` мм, `Layout::SatelliteTopZ`), чтобы прибор был у центра,
  как в `default`; радиус увеличен до самого дальнего угла спутника, `R = 349.5` мм.
  `isotropic_up` / `isotropic_down` — полусферы выше / ниже этой плоскости.
- Нормировка в спутниковых конфигурациях идёт на весь спутник (`S⊥ = 122.8` см² сверху,
  `377` / `440` см² сбоку, `G = 1.46·10⁴` см²·ср у `cubesat` и `4.82·10⁴` у `tunacan` против `2.6·10³` у `default`),
  поэтому для той же статистики нужно в 3–20 раз больше событий. Вырезать спутник из огибающей
  нельзя: его вещество — часть результата.
- Имена `info_*.txt` и каталогов `post_processing/…` для всех конфигураций, кроме `default`,
  получают суффикс, например `…_flat_t0_p0_tunacan_engine-sputnix`; у `default` имена прежние.
  В `info_*.txt` пишутся `Geometry_config`, `Engine`, `Camera`, `Trigger`.
- После построения геометрии `Geometry::CheckEnvelope` проверяет, что каждый объём верхнего уровня
  лежит внутри огибающей и внутри `R_b`, и останавливает прогон, если это не так. При переносе
  двигателя/камеры или изменении размеров спутника достаточно поправить `Layout` — проверка подскажет,
  если огибающая перестала охватывать модель.

## Генерация частиц

Вся генерация и нормировка сосредоточены в классе `GenSurface` (`include/GenSurface.hh`,
`src/GenSurface.cc`): и розыгрыш точки/направления, и площадь, на которую нормируется результат,
берутся из одного объекта.

### Система координат и углы

Ось `+z` — «вверх» прибора. Огибающая модели зависит от `-gc` (см. «Конфигурации геометрии»).
Для `default` это цилиндр радиусом `R = modelRadius` от низа нижнего
колпака до верха банки (`R = 37` мм, `z ∈ [-44.9, 31.5]` мм, центр `z = -6.7` мм).
Ti-пластина в огибающую не входит, но все стартовые точки лежат за пределами всей модели
вместе с пластиной: на расстоянии `R_b ≈ 81` мм от центра (`GenSurface::BoundingRadius`).
Для спутника огибающая — коробка, `R_b` — её полудиагональ + 5 мм (`192.4` мм для `cubesat`,
`218.5` мм для `tunacan`), для `experiment` — `52.2` мм. Сфера `isotropic*` в `tunacan` своя —
с центром на верхе спутника и `R = 349.5` мм (`GenSurface::SphereCentre` / `SphereRadius`).

`θ, φ` задают направление, откуда приходит частица:

```
Arrival(θ, φ) = (sinθ·cosφ, sinθ·sinφ, cosθ),     направление движения = -Arrival(θ, φ)
```

`θ = 0` — сверху вниз, `θ = 180` — снизу вверх, `θ = 90, φ = 0` — с `+x` в сторону `-x`.

### Режимы

| `-fd`            | Старт                                         | Направление                                    | Нормировка                       | Результат         |
|------------------|-----------------------------------------------|------------------------------------------------|----------------------------------|-------------------|
| `isotropic`      | сфера `R_b` вокруг центра огибающей (`tunacan`: см. выше) | внутрь, по закону косинуса                     | `G = 4π²R_b²` [см²·ср]           | чувствительность  |
| `isotropic_up`   | верхняя полусфера                             | то же                                          | `G = 2π²R_b²` [см²·ср]           | чувствительность  |
| `isotropic_down` | нижняя полусфера                              | то же                                          | `G = 2π²R_b²` [см²·ср]           | чувствительность  |
| `flat`           | силуэт огибающей в плоскости ⊥ пучку на `R_b` | `-Arrival(θ, φ)`                               | `S⊥(θ, φ)` [см²]                 | эффективная площадь |
| `point_beam`     | точка `(r cosφ, r sinφ, source-z)`, `r = source-r` | `-Arrival(θ, φ)`                               | `1`                              | эффективность     |
| `point_iso`      | та же точка                                   | равномерно по телесному углу в конусе `α` вокруг `-Arrival(θ, φ)` | `1`           | эффективность     |

Во всех режимах результат по энергии — `norm · N_trig(E) / N_gen(E)`.

### `flat`: плоский поток под произвольным углом

Проекция цилиндра на плоскость, перпендикулярную пучку, — два эллипса (проекции торцов),
соединённые прямоугольником. Её площадь

```
S⊥(θ) = πR²|cosθ| + 2R·H·sinθ,      H — высота цилиндра
```

При `θ = 0/180` это круг `πR²`, при `θ = 90` — прямоугольник `2RH`; от `φ` не зависит.

Точка разыгрывается равномерно в описанном прямоугольнике `2(H/2·sinθ + R|cosθ|) × 2R`, точки вне
проекции отбрасываются и разыгрываются заново (в `N_gen` они не входят). Для любой области `A`
внутри проекции `S` вероятность попадания равна `|A|/|S|`, то есть распределение по проекции строго
равномерное при любой её форме. Каждый луч, выпущенный из проекции вдоль пучка, пересекает цилиндр,
и каждый луч, пересекающий цилиндр, выпускается из проекции.

Для спутника (`-gc tunacan`, `-gc cubesat`) огибающая — коробка с полуразмерами `hx, hy, hz`,
её проекция — шестиугольник (прямоугольник, если пучок вдоль оси коробки), площадь

```
S⊥(θ, φ) = 4·(hy·hz·|aₓ| + hx·hz·|a_y| + hx·hy·|a_z|),     a = Arrival(θ, φ)
```

и зависит от `φ`. Розыгрыш тот же: описанный прямоугольник и отбраковка точек, луч из которых
не пересекает коробку.

### `point_iso`: изотропный источник в конусе

Направление разыгрывается в системе, где ось конуса `n = -Arrival(θ, φ)`:

```
cosβ = 1 - ξ₁·(1 - cosα),     ψ = 2π·ξ₂,     ξ₁, ξ₂ ~ U(0, 1)
dir  = sinβ·cosψ·e₁ + sinβ·sinψ·e₂ + cosβ·n
```

Изотропия означает равномерность по телесному углу: `dΩ = sinβ dβ dψ = d(cosβ) dψ`, поэтому
`cosβ` должен быть равномерен на `[cosα, 1]`, а `ψ` — на `[0, 2π)`. Телесный угол конуса
`Ω = 2π(1 - cosα)`, его доля от полной сферы `f = (1 - cosα)/2`.
При `α = 180` источник изотропен во все стороны, при `α → 0` совпадает с `point_beam`.

Нормировка:

- `ε = N_trig / N_gen` — эффективность относительно частиц, **вылетевших в конус**.
  Именно она лежит в гистограмме и CSV `effective_area` для точечных источников.
- `ε_abs = ε · f` — абсолютная эффективность относительно источника, излучающего изотропно
  в полные `4π` (пишется в `info_*.txt` как `Absolute_*`). Для источника активности `A` [Бк]
  с выходом `y` частиц на распад скорость счёта `= A · y · ε_abs`.

Сужение конуса не меняет `ε_abs`, пока конус целиком покрывает всю модель (включая пластину): `ε` растёт ровно во
столько раз, во сколько падает `f`. Этим можно пользоваться, чтобы не тратить статистику на
частицы, летящие мимо.

### Минимальный радиус точечного источника

Точка не должна оказаться внутри вещества. Допустимый радиус зависит от высоты
(`GenSurface::MinSourceRadius`), запас `5` мм:

| Высота `z`                                          | `r_min`                           |
|-----------------------------------------------------|-----------------------------------|
| в пределах цилиндра (`[-44.9, 31.5]` мм) ± 5 мм     | `R + 5 = 42` мм                   |
| в пределах Ti-пластины (`[-34.5, -31.5]` мм) ± 5 мм | полудиагональ пластины + 5 ≈ 75.7 мм |
| выше или ниже модели                                | `0` — можно ставить прямо на оси  |

Это числа для `default`. Для `experiment` в полосе цилиндра `r_min = 32 + 5 = 37` мм (пластины нет),
для спутника в полосе коробки `r_min = √(hx² + hy²) + 5 ≈ 83.3` мм, выше/ниже спутника — `0`.
Координаты точечного источника — мировые: для спутника `z` отсчитывается от его центра.

Если `--source-r` меньше `r_min`, запуск останавливается с сообщением о минимальном радиусе на этой
высоте. Проверено навигатором Geant4 на реальной геометрии: точки на `r_min` при всех `z` и `φ`
лежат в вакууме мира.

Пример — источник на оси над прибором, конус 20° вниз:

```bash
./GammaCube -i ../run.mac -fd point_iso --theta 0 --source-r 0 --source-z 100 --cone 20
```

### Выходные файлы

Имена `info_*.txt` и каталога `post_processing/…` содержат тег направления, поэтому прогоны
с разными направлениями не перетирают друг друга, например:
`Uniform_particles:gamma_flat_t45_p30`, `…_isotropic_up`, `…_point_iso_t60_p0_r80.9792_z10_c25`.

В `info_*.txt` блок `Generation_surface` описывает использованную поверхность или точку.
Для точечных источников вместо `Rates:` / `Optical_rates:` пишутся `Efficiency:` /
`Optical_efficiency:` — скорость счёта без активности источника не определена.

В GUI поверхность генерации рисуется поверх геометрии (`/vis/scene/add/userAction` в `vis.mac`).
